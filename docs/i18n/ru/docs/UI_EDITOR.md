# UI-редактор и fantasy-HUD (1.1.0)

<a id="benutzung"></a>
## Использование

В обычной игре открыть существующий чат Enter, ввести /UiEdit и отправить. Регистр не важен. Команда доступна всем подключённым игрокам, не принимает параметры и открывает только свой layout. Chat не меняется; UI Core регистрирует uiedit с owner skymp-ui-core в настоящем command-реестре v1. /help может его показывать.

- Нажать/перетащить элемент — свободная позиция.
- Тянуть светлый нижний правый угол или менять «Размер элемента» — индивидуальный масштаб 75–150%. Общий масштаб остаётся дополнительно.
- Для выбранного элемента стрелки двигают на 1 пиксель, Shift — на 10, +/− меняют размер шагом 5%.
- В редакторе доступны видимость, фиксированный угол экрана, язык DE/EN, Reset.
- «Сохранить и закрыть» применяет layout. «Отмена»/Escape отбрасывает изменения после открытия. «Сбросить всё» сохраняется окончательно только при сохранении.

Редактор использует тот же BrowserService-фокус, что UI-меню. Инвентарь/карта/консоль приостанавливают его, после закрытия он возвращается. Disconnect/отсутствие UI Core удаляют представление и освобождают ввод. F6 закрывает как Escape. Без SkyMP Chat остаётся кнопка «Отображение» в осознанно сфокусированном CEF, например F6.

<a id="metabolism-darstellung"></a>
## Отображение Metabolism

Существующий неизменённый адаптер по-прежнему предоставляет ровно один icon-list-widget с сытостью, жидкостью и отдыхом. Общий renderer показывает записи тремя отдельными руническими печатями: руна и число внутри круга, вокруг — кольцо значения в металлической рамке. Название и status-текст больше не выводятся под печатью, только во всплывающей подсказке и для screenreader; поэтому меняющийся текст не может увеличить или сдвинуть элемент. Каждую можно двигать, масштабировать и скрывать независимо. Другие icon-list-потребители тоже используют это представление без изменения UI Core.

Кольцо значения выводится исключительно из полной положительной дроби вроде «85,3/100 · Gut»: максимум — всегда полное кольцо, половина — половина кольца. После максимума допускается единица до трёх букв, например «8/40 m»; в печати тогда стоит «8 / 40 m». Поддерживаются немецкая запятая/английская точка (не более двух знаков после запятой). Неизвестное остаётся текстом в печати с пустым кольцом; клиент не выдумывает игровые значения или правила Metabolism. Состояние окрашивает руну и кольцо: оранжевый для `warning`, красный для `error`, зелёный для `success` у `status`-виджетов. Руны — встроенная простая SVG-геометрия без внешних запросов изображений/шрифтов/платных сервисов.

<a id="sprachreichweite-und-statusanzeigen"></a>
## Голосовая дальность и индикаторы

Обычные `status`-виджеты используют те же руны, металл, шрифты, status-цвета. Отображение целиком принадлежит UI-Core; YACA для `skymp-yaca-ts:voice-range` даёт только дальность, состояние микрофона/звука/речи. Дальность приходит как «8/40 m»: текущая дальность и наибольшая дальность из `voiceRanges.ranges` в `config.json` YACA. Кольцо показывает долю (8 из 40 m = 20 %, 20 m = половина кольца, 40 m = полное кольцо). Состояние микрофона, звука и речи из YACA-сообщений (в том числе при заблокированной дальности) видно только по цвету руны и кольца: золотой — активен, зелёный — речь, оранжевый — микрофон/звук заглушены или нет TeamSpeak. Под печатью больше нет status-текста, поэтому элемент при речи не прыгает. Значение без максимума вроде «8 m» по-прежнему не создаёт вымышленного процентного заполнения.

Widget сохраняет прежний layout-key без `#0`, перемещается/масштабируется/скрывается через `/UiEdit`. Предупреждение TeamSpeak и настройки F8 остаются YACA-UI. Изменение позже требует обновлённый server-plugin YACA и runtime UI-Core; здесь подготовлены только исходники, без сборки/упаковки.

<a id="speicherung-und-sicherheit"></a>
## Хранение и безопасность

Существующий ключ skymp-ui.v1.<preferenceKey> сохраняется. Прежние corner/visibility-настройки переносятся. Новые preferences содержат лишь нормализованные x/y, масштаб, видимость. Они хранятся локально на аутентифицированного игрока с серверным preference-key. При смене разрешения нормализованные позиции остаются видимыми. Без CEF LocalStorage layout работает в текущем сеансе; ошибка сохранения показывается явно.

Читается максимум 160 записей / 64 K символов. Неверные/выходящие за пределы координаты/размеры игнорируются. Записи списков используют <widgetId>#0–#15; порядок потребитель сохраняет стабильным. Metabolism уже использует сытость, жидкость, отдых. Layout и игровые значения на сервер не записываются; menu-actions остаются на прежнем проверенном канале.

<a id="installation--upgrade"></a>
## Установка / обновление

Обновить обе стороны: server-plugin 1.1.0 и соответствующий client-script/CEF. API v1/frontend-protocol v1 сохраняются; поддержка редактора дополнительно согласуется editorVersion: 1 при настоящем Ready. Без маркера сервер редактор не открывает, /UiEdit приватно просит актуальный client-пакет. Старый клиент на новом сервере использует старые widgets. Новому клиенту нужен server-plugin минимум 1.1.0.

Рекомендуется Chat → UI Core; настоящая ограниченная skympChatReady-queue поддерживает и UI Core → Chat без polling. При коллизии команда остаётся прежняя, UI Core пишет конфликт, кнопка отображения доступна. Shutdown удаляет лишь свою регистрацию/ожидающий callback. По-прежнему нужны перезапуски сервера/клиента.

Patch: integration/skymp-fork/ui-core.patch. Для интегрированной установки меняются только uiCoreBridge.ts и созданные features/uiCore/index.js/index.css. Старые BrowserService/root/Chat-hooks остаются. См. CLIENT_DEPLOYMENT.md. Оригинальные checkout SkyMP/Chat/Metabolism/Launcher в этой работе не меняются; сборка/браузер используют artifacts/editor-fork.

<a id="reproduzieren"></a>
## Воспроизведение

    npm run typecheck
    npm test
    npm run integration:plan -- --refresh
    npm run integration:stage
    $env:NODE_PATH='D:\GitHub\skymp\skymp5-front\node_modules'
    Set-Location artifacts/editor-fork/skymp5-front
    npm run build

Staging-копия читает зависимости форка через явные resolution-пути. Нативные тесты могут задавать SKYMP_FORK на staging, SKYMP_NATIVE_FORK на настоящий fork. DLL/игровые данные там только читаются. Для другого checkout задать SKYMP_SOURCE_FORK при staging; план должен ему соответствовать.

Новые тесты проверяют независимую геометрию, локальную миграцию, editor-handshake, нативную идентичность, старых клиентов, ownership команд и настоящую Chat-ready-queue. Browser-run production-root использует двух настоящих Scamp-ботов, client-мосты, неизменённый адаптер Metabolism. SkyrimPlatform menu/browser-callback остаются имитацией. Настоящая Skyrim/CEF-сессия всё ещё требует отдельной приёмки.
